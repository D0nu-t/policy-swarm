Suggest from text

Drafts an opinion space from the policy text in two steps. Both only make suggestions: nothing in the tables below changes until you choose to use them, and everything stays editable.

1. Find topics

A topic model groups the sentences of the policy text into themes. Each theme is a list of words that tend to appear together, and could serve as a dimension. It cannot name a theme or say which way is "positive", so give each one a name and, after using it, a description of what its positive end means.

2. Suggest keyword rules experimental

A decision model (Laya) is asked, for each distinctive topic term that occurs in the policy text: which dimension in the table does it bear on, does it raise or lower it, and how strongly? It reads the dimension descriptions, so write those first. Treat the answers as a first draft. On 104 held-out test phrases about two thirds of the rules it suggested were right (0.66), it found about half of the phrases that deserved a rule (0.49), and it gave a rule to 1 in 6 generic phrases that deserved none. A rule marked with a probability of 0.5 or more is somewhat more likely to be right; that is a weak guide, so check every row.
